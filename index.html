RelayHub

Локальный OpenAI-совместимый шлюз: один endpoint, один ключ, единый каталог моделей.

Что это

RelayHub — локальный шлюз, который принимает запросы AI-клиентов на OpenAI-совместимом API (Chat Completions и Responses, включая SSE-стриминг), публикует единый каталог моделей и маршрутизирует каждый запрос по полю model на настроенный пул upstream-провайдеров или отдельный маршрут — с автоматическим failover.

Возможности

Один endpoint, один ключКлиенты подключаются к локальному адресу шлюза; ключ хранится в системном хранилище ОС, а не в конфигах.
Единый каталог моделейDiscovery и нормализация: клиент видит один список моделей, за которым стоят разные провайдеры.
Пулы и маршрутыТопология из пулов и маршрутов, sticky-привязки, AUTO-маршрутизация, учёт фактических попыток upstream.
FailoverСбой upstream — автоматический перенос запроса на следующий элемент пула, включая mid-stream ошибки.
Responses APIПоддержка Responses-совместимых клиентов: стриминг полного жизненного цикла событий, нормализация tool-вызовов.
Desktop-приложениеОболочка на Tauri 2 + Svelte: топология, статус пулов, квоты и активный трафик без правки конфигов.
Admin APIАутентифицированный control-plane: группы, статус, телеметрия активных запросов без prompt/credential данных.
ПриватностьШлюз живёт на loopback; телеметрия не содержит содержимого запросов, сессий и учётных данных.

Как это работает

клиент ──▶ RelayHub (loopback) ──▶ маршрутизация по model ──▶ пул/маршрут ──▶ upstream │ failover ──▶ следующий upstream

Клиенты (ассистенты, IDE-агенты, любые OpenAI-совместимые приложения) настраиваются один раз — дальше состав и порядок провайдеров меняется в шлюзе, без трогания клиентов.

Стек

  • Бэкенд — Python: HTTP-слой, маршрутизатор, адаптеры upstream, топология пулов/маршрутов, admin API.
  • Оболочка — Tauri 2 + Svelte: desktop-приложение поверх сайдкара.
  • Тесты — HTTP, пул/failover, группы/статус и adapter-регрессии; изолированные smoke-проверки сборки.
